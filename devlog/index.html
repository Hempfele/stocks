🏛️ Fantasy Portfolio — Devlog

Fantasy Portfolio — a lightweight web game: ten areas of life, one stock for each. Pick the companies that reflect the life you want to see, lock €1,000 of each, and watch the season unfold with your co-players.

This devlog is our shared memory: the decisions we make (and the ones we turn down), what we learn, and how we work. New entries land as the game grows.

◆ The goal

A game for two players (eventually more) born from a voice note: represent a whole life as ten areas modeled on the hierarchy of needs — from 🍞 Nourishment up to 🚀 Dreams & Frontier — and pick one stock for each. Picking locks the live price and virtually buys €1,000. Over a season everyone watches the portfolios evolve; at the end there's a winner.

  • Values over analytics — the choice shouldn't be based on price charts; it's about the companies you want to support and the life you want to see.
  • Together — every player sees every other player's picks; the fun is in comparing worldviews.
  • Seasons — picks lock when the season runs, prices reset when a new one starts.

Canonical source: PLAN.md in the repo · original voice note transcript: Fantasy Portfolio.transcript.md.

◆ Requirements & hard constraints

These are load-bearing — we don't drift from them.

  • Lightweight feel. No finance-app energy: numbers stay understated, no charts, no jargon. Picks and their stories come first.
  • No build step. Vanilla ES modules; the repo deploys to GitHub Pages as-is.
  • Demo mode first. Empty js/config.js runs the whole game on fake data — every change is verifiable locally in seconds.
  • Fair scoring across currencies. Each pick is worth €1,000 × (current / locked price) — ratios, so EUR and USD picks compare honestly without FX.
  • Locked means locked. Picks are insert-only and written server-side (edge function fetches the live quote), so locked prices can't be forged and there are no take-backs.

◆ Claude's take

What excites me

  • The reframe: a portfolio as a self-portrait. Ten picks say more about a person than any questionnaire.
  • Ratio scoring quietly solves the multi-currency problem with zero FX code.
  • The whole game is ~600 lines with no build step — it stays understandable.

Curious to explore

  • Pick notes ("why this company") — probably the soul of the game once added.
  • What a season-end "ceremony" should feel like in something this gentle.
  • Whether the areas themselves should be a seasonal theme (e.g. a "cities" season).

Critique & open questions

  • Yahoo's unofficial API is unblessed — fine for a friendly game, but if it breaks, the edge functions are the only place to swap in another source.
  • Demo mode locks picks at season-start prices so the board moves immediately; live mode locks at pick time. Same code path otherwise, but worth remembering when comparing.
  • The weekly notification channel is genuinely undecided (email vs Telegram) — deferred until the game is live and the need is real.

◆ How we work

  • Voice first. Ideas arrive as voice notes; /transcribe (local whisper, nothing uploaded) turns them into transcripts that live next to the idea.
  • Plan, then build. Big decisions get asked as explicit either/or questions before code; the outcomes land in Decisions.
  • Demo mode is the test bench. Every change is verified by playing the game locally (?seed pre-fills a board, ?reset clears it) and screenshotting.
  • This devlog is maintained in parallel. Every working session ends with a dated entry — what changed, decided for/against, a screenshot when visual — plus a timeline refresh. The practice is pinned in the repo's CLAUDE.md.

◆ Decisions

The standing record. Per-entry decisions live in the log below.

Decided for

  • GitHub Pages + Supabase — static frontend, free tier auth/Postgres/edge functions; reachable by a remote player 2. 2026-06-13
  • Magic-link email auth — no passwords, real accounts, scales to more players. 2026-06-13
  • Yahoo Finance via edge functions — US + EU coverage, no API keys in the client, no CORS. 2026-06-13
  • Server-side pick locking — make-pick fetches the quote and inserts; RLS keeps clients read-only on picks. 2026-06-13
  • Ratio-based scoring — €1,000 × current/locked; mixed currencies compare fairly. 2026-06-13
  • Demo mode — empty config runs the full game on fake data. 2026-06-13

Decided against (for now)

  • Raspberry Pi hosting — local-only; awkward for a remote second player.
  • Player codes / Google OAuth — magic links won on friction vs. realness.
  • FX conversion — unnecessary once scoring is ratio-based.
  • Charts & analytics — against the spirit; numbers stay quiet.
  • A build step / framework — vanilla modules keep deploys trivial and the code legible.

◆ Devlog

2026-06-13

From a voice note to a playable scaffold

The game started as a six-minute voice memo recorded on the Desktop. A new reusable /transcribe skill (local whisper, afconvert → 16 kHz WAV) turned it into a transcript; from there came PLAN.md, two explicit architecture decisions, and by the end of the session a fully playable game in demo mode: sign in, name yourself, pick stocks for ten life areas via typeahead search, lock them in, and watch the dashboard compare players — crown included.

Supabase is fully prepared but not yet live: 001_init.sql (schema + RLS) and three edge functions (stock-search, make-pick, refresh-prices) sit in the repo, with the go-live checklist in README.md.

Decided for

  • GitHub Pages + Supabase over Pi hosting (remote player 2 needs a real URL).
  • Magic-link email over player codes and Google OAuth.
  • Ratio scoring (€1,000 × current/locked) — FX problem dissolved.
  • Demo locks at season-start prices so a fresh board moves immediately.
  • ?seed / ?reset URL params as the demo test bench.

Decided against

  • Client-side price locking — too forgeable, even among friends.
  • Any chart library or framework — the whole game is vanilla modules.
  • Building notifications now — channel (email vs Telegram) decided once the game is live.
